# v0.82.0 Implementation Plan — Frontier and CDC Durability Gate

**Status:** Planned  
**Target:** v0.82.0  
**Baseline:** v0.81.1  
**Roadmap:** [roadmap/v0.82.0.md](../roadmap/v0.82.0.md)  
**Last updated:** 2026-08-14

---

## 1. Outcome

v0.82.0 closes every known path where pg_trickle can acknowledge, discard, or
advance past a committed source change before that change is either present in
the stream table or recoverable from durable CDC state.

The release is complete only when these invariants hold:

1. A differential frontier advances only to a bound proven safe against every
   transaction that could have written an invisible change-buffer row.
2. The coordinator's safe bound is immutable input to every job in one
   database-local dispatch tick. Workers never recompute or reread it.
3. A FULL refresh materializes data and establishes its frontier under the same
   protected source snapshot.
4. A WAL slot advances only as a consequence of successfully decoding changes
   into a durable buffer, or an exact snapshot proof covering every consumer.
5. Missing, truncated, malformed, inaccessible, or crash-cleared required CDC
   state aborts differential refresh and leaves the previous frontier intact.
6. Every successful execution path uses one transactional finalizer for data
   visibility, frontier, timestamps, downstream CDC, cleanup, audit history,
   outbox writes, cost data, and configured post-refresh work.
7. `change_buffer_durability` has one strict implementation: `logged` is the
   crash-safe default, `sync` enforces `synchronous_commit = on`, `unlogged`
   has reliable loss detection, and invalid values are rejected.
8. Any unproven condition fails closed. Availability or retained-WAL growth is
   preferable to a false successful refresh.

No new CDC backend, external worker, transport, or general refresh state
machine is part of this release. PostgreSQL transactions remain the atomicity
mechanism.

## 3. Target Design

### 3.1 Safe frontier types and decision rule

Replace the current oldest-xmin comparison with explicit, pure decision state.
The names below are illustrative; keep the implementation in the existing CDC
and watermark modules rather than adding a framework.

```rust
struct FrontierProbe {
    candidate_lsn: PgLsn,
    active_xids: HashSet<u64>,
}

struct FrontierProbeState {
    previous_candidate_lsn: PgLsn,
    writer_fences: HashMap<u64, Option<PgLsn>>,
    last_safe_lsn: Option<PgLsn>,
}

enum SafeFrontierDecision {
    AdvanceTo(PgLsn),
    HoldAt(PgLsn),
    HoldExisting,
    Unavailable(PgTrickleError),
}

struct RefreshTick {
    dispatch_tick_id: i64,
    safe_lsn: PgLsn,
}
```

The probe must capture its candidate LSN before enumerating blockers and must
return all transaction IDs visible through:

- `pg_stat_activity.backend_xid`;
- `pg_stat_activity.backend_xmin`;
- `pg_prepared_xacts.transaction`.

Use one SPI statement with a materialized candidate-LSN CTE. Exclude only the
probing backend. Do not filter out `idle in transaction` writers. Permission,
catalog, NULL-decoding, or malformed-LSN failures are probe failures, not an
empty blocker set.

Each active transaction receives a fence:

- A transaction still present from the prior probe retains its old fence.
- A transaction first observed after a successful prior probe receives the
  prior probe's candidate LSN as its fence.
- A transaction present on the first probe has an unknown fence.
- When a transaction disappears, remove it.
- The safe bound is the minimum known fence among active transactions, never
  below `last_safe_lsn`. If no transactions remain, the current candidate is
  safe. An unknown fence prevents advancement until its transaction ends.

This provides progress under writer replacement without relying on “oldest xid
increased,” which is not a visibility proof. XID wraparound between adjacent
ticks remains guarded by the existing practical assumption and a unit test.

Decision table:

| Probe/state | Result |
|---|---|
| Successful, no active transaction | Advance to current candidate |
| Successful, active transactions all have known fences | Advance/hold at the minimum fence |
| First probe with any active transaction | Hold existing frontiers; do not manufacture a bound |
| Successful probe with an unknown-fence transaction still active | Hold existing/last safe bound |
| Probe failure with a known last safe bound | Hold at the last safe bound |
| Probe failure without a known bound | Do not dispatch differential work; manual refresh returns a typed error or no-advance result |

The current time-based `HOLD_PROBE_CACHE` must not cache a “no blockers” result
across dispatch ticks. One fresh probe per database scheduler tick is sufficient.

`frontier_holdback_mode` may add a stricter cap, but no mode may bypass the
mandatory visibility bound:

- `xmin`: mandatory bound only;
- `lsn:N`: `min(mandatory_bound, current_lsn - N)`;
- `none`: no additional margin, still the mandatory bound.

Document this compatibility-preserving semantic change. The GUC is no longer a
correctness off switch.

### 3.2 Immutable, database-local dispatch input

Add these nullable columns to `pgtrickle.pgt_scheduler_jobs` so historical rows
remain valid:

```sql
dispatch_tick_id   bigint,
tick_watermark_lsn pg_lsn
```

Every newly queued job must have both values. The per-database catalog already
provides database scoping, so a redundant database OID column is unnecessary.
Reject or cancel queued/running legacy jobs without a bound during upgrade or
startup recovery.

Flow:

1. The per-database coordinator allocates one `dispatch_tick_id` and captures
   one `RefreshTick`.
2. Inline work receives that value by reference.
3. `SchedulerJob::enqueue()` stores it with every dynamic job.
4. A dynamic worker loads it from its claimed job and passes it unchanged to
   every member, including atomic, cyclic, repeatable-read, and fused units.
5. Remove worker calls to `compute_worker_tick_watermark()` and retire the
   cluster-global safe-LSN field as a correctness input. Shared memory may keep
   aggregate metrics only.
6. Record the same LSN in refresh history for manual and scheduled work.

Do not enqueue new differential jobs when the coordinator has no safe bound.
Manual differential refresh uses the same probe. If its one-shot probe cannot
advance safely, it retains each source's existing frontier rather than reading
current WAL.

### 3.3 Per-source frontier construction

Replace `get_slot_positions()`, which currently returns the same current WAL
LSN for every source, with one source-aware position collector over validated
dependencies:

| Source mode | Upper position |
|---|---|
| Trigger CDC | The immutable tick/manual safe bound |
| WAL CDC | The last LSN whose decoded events committed to the registered durable change buffer; never raw current WAL |
| Transitioning CDC | The minimum of the exact cutover bound and durably decoded position |
| Foreign/matview polling | The LSN written with the successfully committed local polling snapshot |
| Stream-table source | The validated upstream ST buffer high-water mark captured under the refresh lock/snapshot |

The collector returns `Result<Frontier, PgTrickleError>`. Missing dependency
metadata, positions, or buffers cannot become an empty map or `0/0` fallback.

### 3.4 Snapshot-aligned FULL baseline

Introduce one shared FULL-baseline entry point used by:

- initial population;
- explicit manual FULL;
- scheduled FULL;
- `needs_reinit`;
- missing-frontier fallback;
- adaptive/complexity fallback from differential;
- TopK's safety fallback.

Within the caller's existing outer transaction it must:

1. Load and validate dependencies and buffer metadata.
2. Resolve all local source relations, including partition roots/leaves and
   upstream stream-table storage.
3. Sort relation OIDs and acquire `SHARE` locks in that order. `SHARE`
   conflicts with source DML's `ROW EXCLUSIVE` lock while permitting reads.
4. Acquire all source locks before capturing a bound or reading source data.
5. Capture the per-source positions/frontier after locks are held.
6. Snapshot the target's previous state when exact logical delta or downstream
   propagation is required.
7. Execute the FULL materialization while locks remain held.
8. Return the captured frontier and exact execution result to the common
   finalizer. Do not recompute the frontier after the query.

Source-specific policy:

| Source type | v0.82 protocol |
|---|---|
| Local table / partitioned table | Lock root and relevant descendants in deterministic OID order |
| Materialized view | Lock the local matview before polling/capture/materialization |
| Upstream stream table | Lock its catalog row and storage relation before reading its buffer position and data |
| Foreign table / remote source | Use an existing provider snapshot token only if the FDW can prove one snapshot covers both data and position; otherwise return `SnapshotAlignmentUnavailable` and preserve the old frontier |
| Citus/distributed source | Require the existing per-node frontier/snapshot protocol to return one complete proof; partial node results fail closed |

Do not invent a remote snapshot protocol in this release. Failing an unsupported
FULL refresh is safer than recording a false frontier.

### 3.5 Required change-buffer registry and sentinel

Add one small logged catalog table for both base-table and ST-to-ST buffers:

```sql
CREATE TABLE pgtrickle.pgt_change_buffers (
    buffer_key       text PRIMARY KEY,
    source_kind      text NOT NULL CHECK (source_kind IN ('BASE', 'STREAM_TABLE')),
    source_id        bigint NOT NULL,
    durability       text NOT NULL CHECK (durability IN ('logged', 'unlogged', 'sync')),
    sentinel_token   bigint NOT NULL,
    created_at       timestamptz NOT NULL DEFAULT now(),
    UNIQUE (source_kind, source_id)
);
```

Every managed buffer contains one control row:

```text
lsn = 0/0, action = 'S', pk_hash = sentinel_token, user columns = NULL
```

The row is created only when the buffer is created or deliberately re-baselined;
ordinary source DML never recreates it.

Why one sentinel solves both durability cases:

- A clean restart preserves the sentinel, even when no data-change rows exist.
- PostgreSQL truncates an UNLOGGED buffer after a crash, removing the sentinel.
- New post-crash DML adds `I`/`D` rows but cannot restore the missing sentinel.
- An operator `TRUNCATE` removes the sentinel from logged or unlogged buffers.
- A malformed or wrong buffer cannot satisfy the registered schema and token.

All generated delta SQL must accept only data actions (`I`/`D`) and an LSN
strictly above `0/0`. Buffer counts, compaction, partition detach, DELETE cleanup,
and optional cleanup `TRUNCATE` must exclude/preserve the sentinel. A deliberate
internal `TRUNCATE` must restore the same registered sentinel in the same
transaction before returning success.

### 3.6 Fail-closed CDC validation

Add one `validate_required_change_buffers(st, dependencies)` helper and call it
before polling, no-data detection, compaction, cleanup, delta SQL generation,
TopK/fused eligibility, or frontier construction.

For every required base or ST buffer, validate in one batched catalog/SPI pass:

- registry row and expected stable name;
- relation existence and allowed `relkind`;
- relation persistence matching registered durability;
- required control columns and types (`change_id`, `lsn`, `action`, `pk_hash`,
  plus source columns needed by the dependency);
- readable/selectable relation;
- matching sentinel row;
- required source tracking/dependency metadata.

Return resolved buffer records so downstream code does not repeat discovery.
Optional lifecycle checks may retain boolean helpers, but correctness paths must
use the fallible validator.

On validation failure:

1. Return `PgTrickleError::CdcStateInvalid` with ST, source, buffer, and reason.
2. Preserve the old frontier, timestamps, data, history success state, and
   buffer contents.
3. Mark the ST and all affected dependents `needs_reinit = true` in recovery
   handling after the failed refresh transaction.
4. Rebuild infrastructure through the existing repair path.
5. Keep differential refresh blocked until a successful protected FULL
   reinitialization clears `needs_reinit`.

### 3.7 WAL consumption and ordered cutover

Delete `advance_slot_to_current()` and every call from FULL cleanup. Slot
confirmation may move only when the logical decoder's buffer inserts commit in
the same transaction. An unlogged buffer is not a durable WAL handoff target;
automatic WAL transition therefore remains disabled for buffers registered as
`unlogged`.

Add two nullable fields to `pgt_dependencies`:

```sql
cutover_target text CHECK (cutover_target IN ('TRIGGER', 'WAL')),
cutover_lsn    pg_lsn
```

Reuse `cdc_mode = 'TRANSITIONING'`, `slot_name`, and
`decoder_confirmed_lsn`; do not add a separate cutover service.

#### Trigger to WAL

1. Keep trigger capture active while creating the slot/publication.
2. Decode WAL into the registered logged/sync shared buffer.
3. Acquire source `SHARE` lock to block new DML and wait for in-flight DML.
4. Capture and store the exact `cutover_lsn`.
5. Drain and commit decoded events through `cutover_lsn`; exact confirmed LSN
   comparison replaces the 64 KiB “close enough” threshold.
6. In one transaction, set catalog mode to WAL and drop the trigger while the
   source lock is held.
7. Commit, release the lock, and clear cutover fields.

#### WAL to trigger

1. Acquire the source `SHARE` lock before changing capture infrastructure.
2. Create and verify trigger function/triggers while WAL capture remains live.
3. Capture the exact `cutover_lsn`.
4. Drain WAL through that LSN into the durable shared buffer and verify the
   committed decoder position.
5. Switch the catalog to Trigger and clear transition state in the same
   transaction; commit before releasing source DML.
6. Drop the slot/publication only after the trigger-mode transaction commits.
   Cleanup failure leaks resources safely and is retried.

If the slot is missing or the drain cannot be proven, install trigger capture
under the source lock, mark every dependent ST for FULL reinitialization, and
keep or clean up WAL resources only after future capture is safe. Never report a
normal cutover completion for this recovery path.

### 3.8 Common refresh execution result and finalizer

Executors mutate storage and return one result record; they no longer store
frontiers or complete metadata themselves.

```rust
struct RefreshExecution {
    requested_action: RefreshAction,
    effective_action: RefreshAction,
    frontier: Frontier,
    rows_inserted: i64,
    rows_updated: i64,
    rows_deleted: i64,
    data_changed: bool,
    was_full_fallback: bool,
    downstream_capture_complete: bool,
}
```

Add one fallible `finalize_success(...) -> Result<(), PgTrickleError>` in the
refresh module. Do not add traits or a persistent finalization state machine.

Within the same outer transaction as the data mutation, the finalizer performs:

1. Validate the immutable frontier and required downstream CDC capture.
2. Atomically store frontier, `last_refresh_at`, `is_populated`, effective mode,
   error reset, and conditional `data_timestamp`/`needs_reinit` state.
3. Clean consumed base/ST buffer rows using the post-update minimum consumer
   frontier while preserving sentinels. Cleanup errors abort finalization.
4. Complete refresh history and refresh summary with exact action/count/fallback
   data.
5. Persist exact cost summary inputs.
6. Write normal or embedding outbox rows transactionally when logical data
   changed.
7. Fire transactional subscriptions/notifications and execute configured
   post-refresh actions. Required failures propagate.

After the surrounding transaction commits, update non-authoritative shared
memory caches and emit logs/metrics. A cache or alert failure must not rewrite
durable success state.

No-data semantics are defined once:

- A validated no-data refresh may advance its frontier and `last_refresh_at`.
- It does not advance `data_timestamp`.
- It does not emit downstream CDC, outbox data, or post-refresh maintenance.
- A FULL physical rewrite with an identical logical result uses exact physical
  counts in history but `data_changed = false` for propagation/timestamps.

All paths must route through this finalizer:

- manual differential and FULL;
- scheduled differential and FULL;
- initialization and reinitialization;
- every internal FULL fallback;
- TopK;
- fused SQL and sequential fused-chain members.

Failure recording stays outside successful finalization. Scheduler failures are
written in a fresh transaction after rollback. A manual SQL error rolls back
the caller's transaction, including any provisional RUNNING history row.

### 3.9 Exact TopK and fused accounting

PostgreSQL 18 provides `MERGE ... RETURNING merge_action()`. Use it to return
exact insert/update/delete counts instead of assigning the total to “inserted.”

Add:

```sql
pgtrickle.pgt_refresh_history.rows_updated bigint NOT NULL DEFAULT 0;
pgtrickle.pgt_refresh_summary.total_rows_updated bigint NOT NULL DEFAULT 0;
```

Update SQL-facing history functions/views and outbox metadata accordingly.

For TopK:

- snapshot pre-state when downstream consumers exist;
- run MERGE with `RETURNING merge_action()`;
- derive exact counts and logical change;
- capture the exact pre/post delta for downstream ST buffers;
- finalize through the shared path.

For fused SQL:

- change every node MERGE, including the last, into a data-modifying CTE with
  `RETURNING merge_action()`;
- make the final statement aggregate per-node actions;
- return one exact `RefreshExecution` per node;
- finalize every node in topological order inside the same transaction;
- roll back the entire fused batch if any node execution or finalization fails.

Change `pg_trickle.enable_fused_refresh` default from `true` to `false` at the
start of the release. Keep explicit opt-in for validation. Do not turn the
default back on in v0.82.0; a later release may do so after production evidence.

## 4. Error Model

Add typed variants in `src/error.rs` rather than parsing SPI strings:

```rust
SafeFrontierUnavailable {
    context: String,
    reason: String,
}

SnapshotAlignmentUnavailable {
    source: String,
    reason: String,
}

CdcStateInvalid {
    pgt_id: i64,
    source: String,
    buffer: String,
    reason: String,
}

CdcCutoverUnproven {
    source_oid: u32,
    target: String,
    required_lsn: String,
    confirmed_lsn: Option<String>,
}

RefreshFinalizationFailed {
    pgt_id: i64,
    stage: String,
    reason: String,
}
```

Classification:

| Error | Retryable | Requires FULL reinit | Frontier may advance |
|---|---:|---:|---:|
| Safe frontier unavailable | Yes after probe/state recovery | No | No |
| Snapshot alignment unavailable | No until source protocol/config changes | No | No |
| Missing/malformed/inaccessible CDC state | No until repair | Yes | No |
| Cutover unproven while old capture remains valid | Yes | No | No |
| Cutover gap/slot loss cannot be recovered | No normal retry | Yes, all dependents | No |
| Finalization failure | Depends on underlying typed cause | No by itself | No; entire refresh rolls back |

`CdcStateInvalid` must count as a visible failure but should not repeatedly
suspend before the recovery handler can set `needs_reinit`. Repair and a
successful FULL, not a retry count, clear it.

## 5. Implementation Work Packages

### WP0 — Lock the unsafe paths before refactoring

**Roadmap:** DUR-81-3, DUR-81-5  
**Goal:** Prevent known optional paths from widening the correctness surface
while deeper work lands.

Changes:

1. Set `PGS_ENABLE_FUSED_REFRESH` default to `false` and update its registered
   description.
2. Remove FULL-refresh calls to `advance_slot_to_current()`; retain WAL until
   normal decoding proves consumption.
3. Add the new typed error variants and classification tests.
4. Turn the missing-base-buffer `Ok((0, 0))` preflight into a temporary typed
   error before the complete validator lands.
5. Add failing regression tests for first-tick/probe failure, dropped buffer,
   and WAL FULL fast-forward.

**Exit:** No default execution path uses fused SQL, no FULL path directly
advances a slot, and a missing buffer cannot be recorded as no-data success.

### WP1 — One safe frontier and immutable jobs

**Roadmap:** DUR-81-1

Changes:

1. Extract the pure writer-fence transition function and exhaustive unit table.
2. Replace the xmin-only probe with the compound `backend_xid` +
   `backend_xmin` + prepared-xact probe.
3. Remove cross-tick probe caching and all current-LSN fallback behavior.
4. Add `RefreshTick` to scheduler-loop, inline, manual, group, and fused call
   signatures.
5. Add scheduler job columns and update enqueue/load/claim/recovery code.
6. Delete worker watermark recomputation and correctness reads from
   `TICK_WATERMARK_STATE`.
7. Replace raw slot-position construction with source-aware, fallible frontier
   construction.
8. Record the manual safe bound in refresh history.

**Exit:** Manual and scheduled differential refreshes pass the same
long-transaction matrix; multi-database workers consume only their stored job
bound.

### WP2 — Buffer registry, strict durability, and fail-closed validation

**Roadmap:** DUR-81-4, DUR-81-6

Changes:

1. Add `pgt_change_buffers` and sentinel creation/backfill.
2. Register both base and ST buffers from the existing creation helpers.
3. Update cleanup, compaction, counts, partitioning, repair, and conversion
   helpers to preserve/control sentinels.
4. Implement `validate_required_change_buffers()` and reuse its resolved output
   in refresh/codegen/scheduler/fused paths.
5. Replace `has_st_change_buffer()` fail-open use in correctness paths with a
   `Result`-returning check.
6. Replace the string durability GUC with pgrx's native enum GUC so PostgreSQL
   rejects invalid values at `SET`/config load time.
7. Keep `logged` as the enum/default; document all three values consistently.
8. For registered `sync` buffers, execute
   `set_config('synchronous_commit', 'on', true)` before the first buffer write
   in trigger functions, ST capture, polling, and WAL decoding transactions.
9. Replace `check_unlogged_buffer_crash_recovery()` with sentinel validation.
10. Ensure repair marks every consumer for reinit and cannot by itself re-enable
    differential refresh.

**Exit:** Drop, TRUNCATE, column damage, permission failure, and crash-cleared
buffers all preserve the prior frontier and require a successful FULL repair;
clean restart with a valid sentinel does not.

### WP3 — Snapshot-aligned FULL baseline

**Roadmap:** DUR-81-2

Changes:

1. Implement deterministic source-lock resolution.
2. Add the shared FULL-baseline executor and move frontier construction into it.
3. Move manual and scheduled FULL/reinit/fallback call sites to the shared
   executor.
4. Fold the existing pre-INSERT ST-source LSN snapshot into its returned
   frontier.
5. Return typed alignment errors for unsupported remote/distributed sources.
6. Make lock/query/frontier failures roll back the prior stream-table contents
   and frontier.

**Exit:** A slow FULL plus a concurrent commit proves that the first FULL either
contains the row and covers its position, or omits both and consumes it later.
The same holds for two STs sharing a source.

### WP4 — Exact WAL drain and cutover

**Roadmap:** DUR-81-3

Changes:

1. Add cutover catalog fields and exact LSN comparison helpers.
2. Make decoder position updates conditional on committed buffer writes.
3. Replace the trigger-to-WAL lag threshold with the locked exact-handoff
   protocol.
4. Replace every abort/fallback path with install-trigger-first WAL-to-trigger
   ordering.
5. Separate post-commit WAL resource cleanup from the capture-mode switch.
6. Mark all dependents for FULL when a drain proof is impossible.
7. Update health/restart recovery for either cutover direction.

**Exit:** Tests account for every commit around both cutover boundaries; resource
deletion never precedes future capture and exact drain proof.

### WP5 — Common finalizer for sequential paths

**Roadmap:** DUR-81-5

Changes:

1. Add `RefreshExecution` and exact physical/logical result production for
   normal differential and FULL.
2. Add one `finalize_success()` and make every required operation fallible.
3. Consolidate catalog update helpers into one frontier/timestamp/effective-mode
   update selected by `data_changed` and action.
4. Make downstream capture and cleanup errors abort success.
5. Move manual and scheduled history/outbox/cost/subscription/post-action logic
   into the finalizer.
6. Keep scheduler failure recording in a clean post-rollback transaction.
7. Delete duplicated manual/scheduled success blocks and internal frontier
   storage from executors.

**Exit:** Manual and scheduled runs of the same action produce identical durable
catalog, history, summary, outbox, downstream buffer, and cleanup state.

### WP6 — TopK and fused finalization parity

**Roadmap:** DUR-81-5

Changes:

1. Add exact `merge_action()` accounting and `rows_updated` catalog/API data.
2. Add TopK pre/post downstream capture and route TopK through the finalizer.
3. Change fused SQL to return per-node action counts.
4. Route every fused member through the finalizer in the chain transaction.
5. Remove zero-count fused history and log-only per-node finalization errors.
6. Keep fusion disabled by default after all tests pass.

**Exit:** TopK and explicitly enabled fused chains propagate downstream changes,
record exact metadata, deliver outbox rows, and leave bounded buffers.

### WP7 — Upgrade, documentation, and release gate

## 7. Upgrade and Compatibility Plan

Create `sql/pg_trickle--0.81.1--0.82.0.sql` and update the embedded/current
schema in the normal release workflow.

Migration order:

1. Disable scheduling/dispatch for the migration transaction and cancel stale
   queued/running jobs.
2. Add scheduler job tick columns.
3. Add dependency cutover columns.
4. Add `pgt_change_buffers`.
5. Add `rows_updated` history/summary columns and recreate affected SQL-return
   types/views/functions.
6. Backfill base buffers from `pgt_change_tracking` and ST buffers from
   `changes_pgt_<id>` relations.
7. Classify existing UNLOGGED relations as `unlogged`; classify permanent
   relations as `sync` only when the effective configured value is `sync`,
   otherwise `logged`.
8. Insert sentinels into existing buffers. Because pre-upgrade UNLOGGED history
   cannot be proven, conservatively mark all consumers of existing UNLOGGED
   buffers `needs_reinit = true` before installing their sentinel.
9. Rebuild base trigger functions so registered `sync` buffers enforce the new
   transaction setting.
10. Validate constraints and resume scheduling only after registry/buffer checks
    pass.

Compatibility behavior:

- Existing explicit `enable_fused_refresh = on` settings continue to opt in;
  installations without an override receive the new `off` default.
- `unlogged_buffers = true` remains a deprecated compatibility override for new
  buffer creation and is stored honestly as `unlogged` in the registry.
- `change_buffer_durability` invalid values fail at assignment/config load.
- Existing permanent buffers retain their actual persistence. The migration
  never rewrites a buffer to UNLOGGED.
- Existing frontiers remain canonical, but no post-upgrade differential job
  advances until the new probe establishes a safe bound.
- Interrupted pre-upgrade cutovers are returned to a proven capture mode or
  force dependent FULL reinitialization; no approximate transition resumes.

Upgrade tests must cover v0.81.1 with:

- active and historical scheduler jobs;
- logged, unlogged, and configured-sync buffers;
- shared base buffers and ST buffers;
- pending change rows;
- a `TRANSITIONING` dependency;
- explicit fusion override versus unset default.

### 8.4 Full E2E

Add or extend custom-image tests for operations unavailable in light E2E:

1. Enable `max_prepared_transactions` and make the prepared-transaction test
   mandatory rather than skipped.
2. Run the idle READ COMMITTED, prepared, first-tick, restart, and writer-
   replacement matrix through both manual and scheduler paths.
3. Run a slow FULL with commits blocked/released around the source lock for one
   ST and two STs sharing the source.
4. Test WAL FULL with concurrent commits and assert slot confirmation never
   exceeds the decoded/proven LSN.
5. Test exact trigger-to-WAL and WAL-to-trigger handoffs with commits immediately

6. Inject missing slot, decoder failure, trigger-create failure, and cleanup
   failure; assert resources are retained or all dependents require FULL.

## 11. Risks and Mitigations

| Risk | Mitigation |
|---|---|
| FULL refresh blocks source DML for its duration | Use the weakest lock that conflicts with source writes (`SHARE`), deterministic ordering, lock timeout with context, and clear operator metrics. Do not weaken snapshot alignment. |
| Busy systems always have some writer | Writer fences permit safe progress as old writers are replaced; avoid the incorrect global “any writer means stall forever” rule. |
| Multi-database scheduler overwrites another database's bound | Store bounds in each database's job rows and pass them explicitly; shared memory is metrics-only. |
| Sentinel leaks into delta math or counts | Reserve action `S`, LSN `0/0`, require `I`/`D` filters, and cover every cleanup/count path in unit/E2E tests. |
| UNLOGGED sentinel loss forces expensive FULL work | This is the explicit unlogged trade-off; default remains logged. |
| `sync` adds commit latency | Apply only to buffers registered as sync; expose the mode and benchmark it. |
| WAL cleanup fails after safe cutover | Retain/retry orphan resource cleanup; leaked WAL is safer than a capture gap. |
| Finalizer increases transaction/lock duration | Remove duplicate SPI calls while consolidating. Split only non-authoritative post-commit metrics; required data/outbox/post-action work stays transactional. |
| Fused rewrite cannot return reliable per-node results | Leave fusion disabled and use the sequential chain path. Do not approximate. |
| Foreign/distributed source cannot provide one snapshot proof | Fail FULL closed with an actionable typed error; do not synthesize a local current-LSN frontier. |
| Upgrade cannot prove pre-v0.82 UNLOGGED history | Force affected consumers through one protected FULL reinitialization. |

Safe rollback for operational trouble is to disable fusion and use sequential
refresh, retain buffers/WAL, and pause affected STs. Never roll back by widening
a frontier, truncating a buffer, or advancing a replication slot.

## 12. Suggested Pull Request Sequence

Keep each PR independently safe and merge in this order:

1. **Guardrails:** fusion off, remove direct slot fast-forward, typed missing
   buffer failure, red regression tests.
2. **Safe frontier:** writer-fence probe, manual parity, immutable job bounds,
   migration columns.
3. **CDC state:** registry, sentinel, strict durability enum, real sync writes,
   repair/reinit gate.
4. **FULL/WAL:** protected FULL baseline and exact bidirectional cutover.
5. **Finalizer:** sequential/manual unification and exact durable metadata.
6. **TopK/fusion:** exact counts, downstream propagation, fused parity while
   remaining default-off.
7. **Release gate:** upgrade coverage, crash/concurrency matrix, docs, ADRs, and
   full CI.

Do not merge a PR that introduces a new frontier/cutover/finalization path with
log-only error handling or without its targeted regression test.

## 13. Definition of Done

- [ ] Manual and scheduled refresh use the same fail-closed safe-bound contract.
- [ ] Probe covers `backend_xid`, `backend_xmin`, and prepared transactions.
- [ ] First tick, restart, probe failure, and writer replacement cannot advance
      past an invisible change.
- [ ] Dynamic workers use only the bound stored with their database-local job.
- [ ] All FULL variants use one protected source snapshot and captured frontier.
- [ ] No FULL path calls `pg_replication_slot_advance()` to current WAL.
- [ ] Both CDC cutover directions use a source lock and exact drain LSN.
- [ ] Invalid required CDC state raises a typed error, preserves frontier, and
      requires repair plus successful FULL reinitialization.
- [ ] Buffer sentinels distinguish clean empty restart from crash/truncation and
      survive internal cleanup.
- [ ] `change_buffer_durability` rejects invalid values, defaults to logged, and
      implements sync for every writer.
- [ ] All success paths use one finalizer and exact metadata.
- [ ] TopK propagates downstream CDC and records exact counts.
- [ ] Fused execution is default-off and, when explicitly enabled, satisfies the
      same finalization contract per node.
- [ ] Upgrade from v0.81.1 is complete and conservatively reinitializes existing
      unlogged consumers.
- [ ] Unit, integration, light E2E, full E2E, TPC-H, dbt, upgrade, CNPG, soak,
      multi-database, and benchmark gates pass.
- [ ] Every release-gate source/ST reconciliation matches exactly.
- [ ] `just fmt` and `just lint` pass with zero warnings.
