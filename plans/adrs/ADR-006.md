# ADR-006: Fail-Closed Semantic Admission

| Field | Value |
|-------|-------|
| **Status** | Accepted |
| **Date** | 2026-08-15 |
| **Deciders** | pg_trickle core team |
| **Category** | DVM correctness / safety |

## Context

Incremental maintenance is valid only when the parsed query and every rewrite
are covered by a semantic proof. Best-effort AST conversion, volatility
inspection, or operator classification can otherwise produce a successful
refresh with incorrect PostgreSQL results.

## Decision

Creation, ALTER, preview, initialization, and refresh planning use one
structured admission result. Unsupported or uninspectable forms are FULL-only:
`AUTO` resolves to FULL, while explicit `DIFFERENTIAL` and `IMMEDIATE` reject
before mutating stream-table state. Inspection errors are reported with an
issue code, operator, reason, and remediation hint; they are never converted to
synthetic SQL or a successful no-op.

## Consequences

Some previously accepted explicit incremental definitions now require `FULL`
or `AUTO`. The conservative behavior protects correctness and makes the
remaining incremental surface auditable.
